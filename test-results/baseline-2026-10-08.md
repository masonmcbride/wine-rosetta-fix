## Method and expected behavior

All hardware probes remotely set a newly created suspended thread, then resume and wait at most 3 seconds. Each Wine process has a 15-second outer timeout; initial wineboot has 60 seconds. A ninth exception aborts the process to bound refiring. Generated code: two NOPs, MOV EAX,1, RET (RET 4 for x86); alternate entry MOV EAX,2, RET. Initial resume-PC cases use PC read from the suspended context; entry cases break at the first generated NOP; later cases break after two NOPs. No guest executable or Wine instruction bytes were patched.

Expected execution fault: EXCEPTION_SINGLE_STEP (0x80000004), handler PC=DR0, DR6.B0=1; duplicate DR0/DR1 enables expect B0/B1 reporting (low bits 3). These are expected semantics, not measurements from Windows in this session. DR7=1 enables local DR0 execution; DR7=5 enables local DR0 and DR1 execution. TF=0. Handler disable clears DR7; redirect additionally sets PC to alternate entry; unchanged returns without context edits; RF handler sets EFlags.RF without disabling DR7.

RF at the actual resume PC should suppress that initial fault and permit completion. A zero-hit result is inconclusive when the RF-clear control also has zero hits. Likewise handler continuation, B0/B1 and no-refire behavior cannot be validated if delivery never reaches the handler.

## CALL/RET stack measurements

The callee begins with MOV SP to a global followed by RET. The caller records SP before CALL and immediately after RET, before restoring SP for safe probe cleanup. TF cases record exception SP and eight raw bytes at that SP, then clear TF before the callee executes. Thus actual callee SP is observed after exception continuation. This distinguishes reporting-only discrepancies from state used by resumed execution, but cannot identify whether Rosetta execution, saved context, or Wine restoration first introduced the error.

bits=32 TF=0 hits=0 before=0036FBCC callee_actual=0036FBC8 callee_context=00000000 after_RET_actual=0036FBCC expected_return=00401614 expected_delta=4 actual_delta=4

bits=32 TF=1 hits=1 before=0036FBCC callee_actual=0036FBC4 callee_context=0036FBC4 after_RET_actual=0036FBC8 expected_return=004015E8 expected_delta=4 actual_delta=8

In the TF-on x86 byte window `e8 15 40 00 00 00 00 00`, the low four bytes decode to return PC `0x004015e8`, matching the expected label; the upper four bytes are zero. The x64 window `ee 15 00 40 01 00 00 00` decodes to `0x1400015ee`. Expected architectural return-address widths are four and eight bytes respectively; the actual store width was not independently measured.

Interpretation: ordinary x86 CALL/RET without TF is the control. TF-on x86 changes both reported and subsequently executed stack state; inspect the raw values above. The eight-byte read is a byte window, not by itself proof of an eight-byte architectural return-address store. Little-endian low four bytes encode the x86 expected return PC; upper bytes must not be mistaken for proof of store width. No stack correction was applied except restoring the original SP after measurement so the standalone test can exit safely.

## Upstream design boundary

Execution observation most naturally lives in `dlls/ntdll/unix/signal_x86_64.c`: context application (NtSetContextThread/set_thread_wow64_context), trap_handler, save_context/restore_context, handle_syscall_trap and setup_raise_exception. NtContinueEx in unix/server.c routes through signal_set_full_context. unix/thread.c translates native/WOW64 server contexts; wow64cpu/cpu.c translates exception state and clears TF during exception preparation. Keep server/mach.c Patch 1 shadow storage unchanged.

Existing ntdll exception bpx_handler variants test execution PC, B0/BS and rearming. test_single_step_address covers context-entry stepping; test_hwbpt_in_syscall covers data watchpoints rather than execution. The WineCX WIP prototype uses per-thread internal stepping and trap interception, but its continuation/rearm logic and x86 CALL correction are not established upstream fixes.

Recommendation: a separate opt-in Rosetta x86_64 execution-breakpoint experiment first. Keep application TF separate from internal stepping and use existing exception dispatch; explicitly handle initial/resumed PC, RF and unchanged-register continuation. Risks include syscall/WOW64 stack transitions, signal safety, reentrancy, context synchronization and performance. Investigate the x86 CALL discrepancy separately; a +4 ESP adjustment is not justified as a general semantic fix by these measurements alone.
